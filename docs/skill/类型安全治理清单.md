## 2. 治理原则

1. **不运动式清零**。目标是「新增代码零显式 `any`」，存量按模块在改动时顺手治理，不单独开大重构。
2. **优先治理边界，不急内部**：props、emit 载荷、服务返回值、store 数据结构——这些是类型传播的源头，改一处下游全部受益。
3. **`unknown` 优先于 `any`**：`unknown` 保留类型安全，使用前必须收窄；`any` 直接关闭检查。
4. **能用推导就别手写**：类型可由初始化值、函数返回值推导时，删掉显式标注比补一个正确的类型更好。
5. **不要为了消 `any` 引入复杂泛型**：如果替代方案比 `any` 更难维护，暂时保留并记录原因。

## 3. 替代方案对照

按出现频率从高到低：

| 场景 | 现状 | 推荐替代 |
|------|------|----------|
| 多源数据归一（图片 / 视频 / 攻略混装） | `item: any` | 定义判别联合类型，用 `type` 或 `kind` 字段收窄：`type FeedItem = ImageItem \| VideoItem \| GuideItem` |
| 组件 props 结构不明确 | `props: { x: any }` | 用 `defineProps<{ x: XxxType }>()`，类型提到 `types.ts` 共用 |
| 事件载荷 | `emit('x', item as any)` | 在 `defineEmits<{ x: [item: XxxType] }>()` 里声明 |
| 跨模块结构相似的字段 | `(item as any).location` | 抽公共接口 `interface WithLocation { location?: string }`，用 `satisfies` 校验 |
| 数组元素缺失类型 | `Ref<any[]>` | `Ref<Item[]>`；若确实异构则用联合类型数组 |
| 动态 key 对象 | `[key: string]: any` | `[key: string]: unknown`，取值时收窄；或明确联合字面量 key |
| 第三方库返回 untyped | `const x = lib() as any` | 优先找官方 `.d.ts`；没有则写最小 `declare` 声明，只用实际访问的字段 |
| 确实无法收窄的动态逻辑 | `as any` | 保留，但加注释说明原因与解除条件；不要静默使用 |

**工具语法**（均属 TS 稳定特性，可放心用）：

- `satisfies` —— 类型校验同时保留字面量推断
- `import type` —— 类型导入与值导入分离，避免运行时副作用
- `as const` —— 字面量推断
- `unknown` + 类型守卫 / `typeof` / `in` 收窄
- `// @ts-expect-error` —— 必须说明理由；项目当前 0 处 `@ts-ignore`，保持

## 4. 治理顺序

按「收益 / 改动面」排序，从高到低：

1. **共享类型定义**：`composables/landscape/profile/types.ts`（`data: any`）、`constants/landscape/chinaRegions.ts`（`[key: string]: any`）—— 一处改动影响大量下游。
2. **服务层**：`services/history.ts`、`services/landscape.ts` —— 返回类型收紧后，调用方自然受益。
3. **profile 转换链**：`useProfileTransform.ts`、`useProfileItems.ts`、`useProfileStats.ts` —— 判别联合的主战场。
4. **TravelGuide 组件**：按重灾区表格逐个处理，先从 props / emit 边界开始。
5. **零散 `as any`**：遇到一处改一处，不专门开批次。

---

## 5. 验收

- `npm run typecheck` 全绿（治理前后都必须绿，不允许用 `any` 换绿）。
- 每批治理后统计：`grep -r ': any\|as any' src --include=*.ts --include=*.vue | wc -l`，数字应下降。
- 如果用户要求开启 `@typescript-eslint/no-explicit-any`：**先只 warn 不 error**，且仅对新增代码生效；存量 error 会造成大面积红灯，得不偿失。
