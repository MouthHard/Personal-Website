# 构建调试与性能优化技巧

> 项目实战中积累的构建排错、工具使用和性能优化经验

## 一、SCSS 构建错误快速定位

### 问题

`npx vite build` 报 `Error: unmatched "}"` 时，错误信息只有 stack trace，无具体行号。

### 解决

用 `sass` 单独编译目标文件，输出精确行号：

```bash
npx sass src/路径/目标文件.scss --no-source-map
# Error: unmatched "}".
#   ╷
# 628 │ }
#   │ ^
#   ╵
```

### 适用场景

- SCSS 嵌套深，大括号匹配难以肉眼检查
- `vite build` 错误信息不够精确时

## 二、edit 工具替换 SCSS 的缩进陷阱

### 问题

`edit` 的 `oldString` 缩进与文件实际缩进不一致时，工具仍可能匹配成功，但替换后缩进错乱，引发大括号不匹配。

### 预防

- 替换前先 `read` 目标区域，确认实际缩进（空格数）
- `oldString` 每行缩进须与文件完全一致
- 替换含嵌套选择器的块后，立即构建验证

## 三、图片加载性能优化

### 原则

| 手段 | 说明 |
|------|------|
| `loading="lazy"` | 首屏外图片延迟加载，减少初始请求 |
| AVIF/WebP 格式 | 比 PNG/JPEG 小 30-50%，项目已迁移首页图片至 AVIF |
| 本地化大图 | 远程图片不可控且慢，关键资源须本地化 |
| CSS 替代图片 | 过渡动画、装饰渐变用 CSS 实现，减少网络请求 |

### 验证

DevTools → Network → Slow 3G，刷新页面观察加载反馈，确认无长时间空白。

## 四、分批改动与构建验证流程

大幅改动时避免积累错误：

1. **构建基线**：改动前先 `npx vite build` 确认当前可构建
2. **分批改动**：按模块分批编辑，每批改完构建验证
3. **即时修复**：每批构建失败立即定位修复，不带着错误继续改
4. **最终全量**：全部改完后再跑一次完整构建

### typecheck 注意

项目 `npm run build` 内含 `vue-tsc --noEmit`。部分模块（如 Search、TravelGuide）可能有预存的类型错误，与本次改动无关。若仅需验证样式/模板改动，可用 `npx vite build`（跳过 typecheck）快速验证。
