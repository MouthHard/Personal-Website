## 一、TypeScript / 逻辑精简

### 1. 删除空函数与死代码

**原则**：函数体只有注释或 `void` 表达式而无实际逻辑的，应删除函数及其所有引用。

**实践**：
```ts
// ❌ 空函数
const handleMore = () => { /* 查看更多处理 */ };
const onImageLoad = (_i: number) => { /* 图片加载完成 */ };
const handleShare = (_p: Platform) => { void _p; };

// ✅ 删除函数 + 模板中的 @click/@load/@share 绑定
```

**依据**：Clean Code 第 3 章"空函数是谎言"——函数名暗示了行为但什么都不做，误导读者。ESLint 规则 `no-empty-function`、`@typescript-eslint/no-unused-vars` 均会标记此类代码。

### 2. 删除永远不变的状态

**原则**：`ref` 声明后从未被赋新值（或只在永远不会触发的分支中赋值），属于死代码。

**实践**：
```ts
// ❌ isLoading 永远是 false，loadMoreTopics 是同步的
const isLoading = ref(false);
const loadMore = () => { if (isLoading.value) return; ... };

// ✅ 删除 isLoading 及所有依赖它的模板分支
```

**依据**：Facebook 的 "Eliminate Dead Code" 指南；Webpack/Terser 的 tree-shaking 原理——死代码应在源码层而非构建层消除。

### 3. 内联一层包装函数

**原则**：函数体只调用另一个函数且无额外逻辑，应内联。

**实践**：
```ts
// ❌ resumeAutoPlay 只是调用 startAutoPlay
const resumeAutoPlay = () => { startAutoPlay(); };
// 模板: @mouseleave="resumeAutoPlay"

// ✅ 直接用原函数
// 模板: @mouseleave="startAutoPlay"
```

**例外**：包装函数提供了语义命名（如 `getGlobalId = String` 在多处使用），内联反而降低可读性时保留。

**依据**：Martin Fowler《Refactoring》"Inline Function" 重构手法；Airbnb Style Guide 建议避免无意义的间接层。

### 4. 合并同模块 import

**原则**：同一模块的多行 import 应合并为一行。

```ts
// ❌
import { useInteractionStore } from '@/stores/landscape';
import { useLandscapeDataStore } from '@/stores/landscape';

// ✅
import { useInteractionStore, useLandscapeDataStore } from '@/stores/landscape';
```

**依据**：ESLint `no-duplicate-imports` 规则；Google TypeScript Style Guide §3.4.3。

### 5. 合并重复的生命周期钩子

**原则**：多个 `onUnmounted`/`onMounted` 应合并为一个，集中清理逻辑。

```ts
// ❌ 两个 onUnmounted
onUnmounted(() => { observer?.disconnect(); });
// ... 其他代码 ...
onUnmounted(() => { document.body.style.overflow = ''; });

// ✅ 合并
onUnmounted(() => {
  observer?.disconnect();
  document.body.style.overflow = '';
});
```

**依据**：Vue 官方风格指南建议生命周期钩子逻辑集中；多个相同钩子增加维护心智负担。

### 6. 提取重复的 toggle 逻辑

**原则**：like/love/favorite 三个函数结构高度相似，应提取公共逻辑。

```ts
// ❌ 三个几乎相同的函数
const toggleLike = (item) => { const r = store.toggleLike(toItem(item)); r ? msg.like.success() : msg.like.cancel(); };
const toggleLove = (item) => { const r = store.toggleLove(toItem(item)); r ? msg.love.success() : msg.love.cancel(); };
const toggleFav  = (item) => { const r = store.toggleFav(toItem(item));  r ? msg.fav.success()  : msg.fav.cancel(); };

// ✅ 提取公共逻辑
const createToggle = (storeFn, msgApi) => (item) => {
  const added = storeFn(toItem(item));
  added ? msgApi.success(item.title) : msgApi.cancel();
};
const toggleLike = createToggle(store.toggleLike, msg.like);
```

**依据**：DRY 原则（*The Pragmatic Programmer*）；Martin Fowler "Extract Method" 重构。

### 7. computed 省略多余 return

```ts
// ❌ 单行逻辑不需要块体
const list = computed(() => { return data.value.slice(0, n); });

// ✅ 箭道式更简洁
const list = computed(() => data.value.slice(0, n));
```

**依据**：Airbnb Style Guide "use arrow function shorthand"；Prettier 默认格式化偏好。

### 8. 精简超长函数的默认值

**原则**：函数中大量 `|| defaultValue` 的属性，如果默认值从未被实际使用（数据源始终提供该字段），属于防御性过度。

**依据**：Clean Code "Defensive Programming Overkill"；应通过类型系统（TypeScript `required` vs `optional`）而非运行时默认值来约束。

## 二、HTML / 模板精简

### 1. 删除纯包装 div/span

**原则**：div 只包含一个子元素且无独立样式/语义作用，应删除。

```html
<!-- ❌ image-container 只包了一个 img -->
<div class="image-container"><img ... /></div>

<!-- ✅ 直接用 img（样式移到 img 上） -->
<img class="image-container" ... />
```

**注意**：删除前确认该 div 是否被 CSS 用作定位上下文（`position: relative`）或 flex 子项。

**依据**：HTML5 Boilerplate "Avoid unnecessary divs"；Google HTML/CSS Guide "Reduce unnecessary nesting"。

### 2. 删除无意义的事件修饰符

```html
<!-- ❌ 该元素没有 click 事件，@click.stop 无意义 -->
<div class="time" @click.stop>{{ date }}</div>

<!-- ✅ -->
<div class="time">{{ date }}</div>
```

### 3. 重复结构改 v-for

```html
<!-- ❌ 5 个结构相同的 stat div -->
<div class="stat"><ThumbUpIcon /> {{ likes }}</div>
<div class="stat"><HeartIcon /> {{ loves }}</div>
<div class="stat"><BookmarkIcon /> {{ favors }}</div>
...

<!-- ✅ 用 v-for 循环 -->
<div v-for="s in stats" :key="s.key" class="stat">
  <component :is="s.icon" /> {{ s.value }}
</div>
```

**依据**：Vue 官方风格指南 "v-for for repetitive structures"；DRY 原则。

### 4. 装饰元素用 CSS 伪元素

```html
<!-- ❌ 纯装饰的 div -->
<div class="hover-indicator"><div class="indicator-ring"></div></div>

<!-- ✅ 用 ::before / ::after -->
```

**依据**：CSS Tricks "Pseudo-elements for decoration"；避免装饰性 DOM 节点增加渲染负担。

## 三、CSS / SCSS 精简

### 1. 删除未使用的选择器

**方法**：构建后搜索 DOM 中不存在的 class，或用工具（PurgeCSS、UnCSS）自动检测。

**注意**：动态 class（`:class="`card-${i}`"`) 容易误删，需配置 safelist。

### 2. 删除空规则

```scss
// ❌ 空规则
.empty-rule { }

// ❌ 只有注释
.placeholder { /* TODO */ }
```

**依据**：stylelint `no-empty-rule`、`comment-empty-line-before` 规则。

### 3. 合并重复属性

```scss
// ❌ 两个选择器重复 5 个属性
.a { color: red; font-size: 14px; margin: 0; padding: 0; border: none; }
.b { color: red; font-size: 14px; margin: 0; padding: 0; border: none; background: #fff; }

// ✅ 用 @extend 或 mixin 提取公共属性
%base { color: red; font-size: 14px; margin: 0; padding: 0; border: none; }
.a { @extend %base; }
.b { @extend %base; background: #fff; }
```

### 4. SCSS 嵌套不超过 4 层

**依据**：SMACSS 架构指南；深嵌套生成过长的选择器，影响性能且难以维护。

```scss
// ❌ 5 层嵌套
.parent { .child { .grandchild { .deep { .deeper { } } } } }

// ✅ 最多 3-4 层，用 BEM 或扁平选择器
.parent__child__deep { }
```

### 5. 用 CSS 变量替代重复值

```scss
// ❌ 同一颜色硬编码 10 次
.a { color: #d4a84b; }
.b { border-color: #d4a84b; }

// ✅ 定义一次
:root { --gold: #d4a84b; }
.a { color: var(--gold); }
.b { border-color: var(--gold); }
```

**依据**：Google CSS Guide "Use CSS custom properties for repeated values"；原生 CSS Variables 浏览器支持率 > 96%。

## 四、精简流程与验证

### 分批执行策略

| 批次 | 内容 | 风险 | 验证方式 |
|------|------|------|----------|
| 第一批 | 删空函数、内联包装、合并 import、删死代码 | 低 | `npx vite build` |
| 第二批 | 提取重复逻辑、合并相同函数、精简超长函数 | 中 | build + 功能测试 |
| 第三批 | HTML 删多余 div、改 v-for、删无意义修饰符 | 中 | build + 视觉对比 |
| 第四批 | SCSS 删未使用/空规则/重复样式 | 需逐个确认 | build + 视觉对比 |

### 验证原则

1. **每批改动后构建验证**：`npx vite build`，不积累错误
2. **UI 外观不变**：装饰性改动不改变视觉效果，功能改动不改变交互行为
3. **Props/Emits 不变**：组件对外接口保持不变，不影响父组件
4. **typecheck 注意**：项目可能有预存类型错误（与本次改动无关），用 `npx vite build` 跳过 typecheck 快速验证
