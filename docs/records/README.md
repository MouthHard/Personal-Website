# 代码修改记录体系

> **用途**：本目录按 `src/pages` 结构组织，记录每次代码修改的思考过程、方案选择、实现逻辑和验证结果。
> **读者**：新会话的 AI 助手或开发者，通过这些记录理解"为什么代码是这样写的"。

---

## 为什么要记录

代码只记录了"做了什么"（what），但不记录"为什么这样做"（why）和"考虑了哪些方案"（how）。
当后续需要修改时，如果没有这些上下文，容易：
- 重复已经否决的方案
- 破坏之前精心设计的约束
- 误解代码的意图

## 记录什么

每次修改记录以下内容：

| 维度 | 说明 |
|------|------|
| **背景** | 为什么要改？用户反馈了什么问题？ |
| **方案对比** | 考虑了哪些方案？各自优缺点？为什么选了这个？ |
| **实现逻辑** | 关键代码的设计思路、数据流、边界处理 |
| **踩坑记录** | 遇到了什么问题？根因是什么？怎么解决的？ |
| **验证结果** | 构建是否通过？功能是否正常？性能如何？ |
| **后续待办** | 还有什么没做完？下一步计划？ |

## 怎么记录

1. **目录结构**：按 `src/pages` 的页面维度组织，公共组件放 `common/`
2. **文件命名**：用中文描述性命名，如 `取景器弹窗子组件提取.md`
3. **时机**：每次完成一组相关修改后，及时记录
4. **粒度**：一个记录文件对应一次完整的修改任务，不拆太碎

## 目录结构

```

├── README.md          # 本文件

```
