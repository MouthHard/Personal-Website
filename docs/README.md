# docs 文档体系总原则

> **本文件是 `docs/` 下所有文档的最高准则，每个子文件夹都必须遵守。**

---

## 核心原则：持续迭代

**docs/ 下每一个子文件夹及其文档，都必须经过大厂、市场、热门、GitHub 项目的规范来进行迭代。**

每次执行任何文档相关的操作前，都要：
1. **检查业界最新实践**：大厂规范（Google/Microsoft/Apple、阿里、腾讯等等国内大厂）、热门开源项目、GitHub 高星仓库
2. **对比当前文档**：找出差距和可改进点
3. **迭代更新**：将更好的实践融入文档，保持文档不过时

## 子文件夹职责

| 文件夹 | 职责 | 迭代参考来源 |
|--------|------|-------------|
| `github-upload-guide.md` | GitHub 上传规范 | GitHub 官方文档、流行开源项目的 CONTRIBUTING.md |
| `skill/` | 项目健康检查与维护手册 | Vue/Vite 官方指南、web.dev、Google Lighthouse |
| `records/` | 代码修改记录（按 src/pages 结构） | ADR（架构决策记录）最佳实践 |
| `bugs/` | Bug 记录与解决方案 | GitHub Issues、 Sentry/Bugsnag 的 bug tracking 规范 |

## 文档质量标准

每份文档必须：
- **有明确的读者**：新会话的 AI 助手或开发者
- **有自迭代提醒**：顶部声明"每次执行前检查业界实践并迭代"
- **有可操作的流程**：不是空谈原则，而是具体步骤
- **有验证标准**：怎么知道做对了
- **保持简洁**：信息密度高，不废话
