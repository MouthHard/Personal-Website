# Vite base 路径导致图片 404

> 日期：2026-10-30
> 模块：PageChange 过渡组件

---

## 症状

过渡图本地化后，图片仍然不显示。Console 日志显示 URL 为 `/change/1.webp`，但 dev server 返回 404。

## 根因

`vite.config.ts` 中 `base: "/Personal-Website/"`，应用部署在子路径下。代码中 `CHANGE_IMAGE_BASE = '/change'` 生成路径 `/change/1.webp`，但 dev server 只在 `/Personal-Website/` 下提供服务，`/change/1.webp` → 404。

## 排查过程

1. 检查 Console 日志：URL 为 `/change/1.webp`
2. `curl http://localhost:5173/change/1.webp` → 404
3. `curl http://localhost:5173/Personal-Website/change/1.webp` → 200 OK
4. 发现 `vite.config.ts` 中 `base: "/Personal-Website/"`
5. 代码中路径缺少 base 前缀

## 方案对比

| 方案 | 做法 | 优缺点 |
|------|------|---------|
| **用 import.meta.env.BASE_URL** ⭐ | `${import.meta.env.BASE_URL}change` | ✅ dev/prod 都正确，不硬编码 |
| 硬编码 base | `/Personal-Website/change` | ❌ base 改了要改代码 |
| 相对路径 | `./change` | ❌ 依赖当前路径，不可靠 |

## 最终方案

```typescript
export const CHANGE_IMAGE_BASE = `${import.meta.env.BASE_URL}change`;
```

`import.meta.env.BASE_URL` 在 Vite 中返回 base 配置值，dev 和 prod 都正确。

## 验证

- dev server 图片 200 OK ✓
- 构建产物中路径为 `/Personal-Website/change/1.webp` ✓

## 预防

- 所有引用 `public/` 资源的路径，都用 `import.meta.env.BASE_URL` 拼接
- 不要硬编码 base 路径
- `index.html` 中的 `<link rel="preload">` 在 dev 模式下不会被 Vite 自动加 base 前缀，需注意
