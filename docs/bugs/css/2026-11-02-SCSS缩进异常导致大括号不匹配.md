# SCSS 缩进异常导致大括号不匹配

> 日期：2026-11-02
> 模块：VisualFeast 取景器弹窗

---

## 症状

编辑 `ViewfinderModal/index.scss` 添加 `.visa-footer` 样式后，`npx vite build` 报错：`Error: unmatched "}"`。`vite build` 的错误信息只给出 stack trace，未显示具体行号。

## 根因

使用 `edit` 工具替换 `.es-date` 样式块时，`oldString` 中 `.es-date` 使用了 4 空格缩进，替换后 `.es-date` 被多包了一层缩进，导致其后多出一个闭合 `}`：

```scss
  .es-loc {
    ...
  }

    .es-date {      // ← 4 空格缩进（应为 2 空格）
      ...
    }
  }                 // ← 多余的闭合
}                   // entry-stamp 闭合
```

实际应为：

```scss
  .es-loc {
    ...
  }

  .es-date {        // 2 空格缩进
    ...
  }
}                   // entry-stamp 闭合
```

## 排查过程

1. `npx vite build` 报 `unmatched "}"`，但无行号
2. `npx sass <file> --no-source-map` 单独编译，精确定位到第 628 行 `}`
3. 读取 SCSS 文件对应区域，发现 `.es-date` 缩进 4 空格（同级 `.es-port`/`.es-loc` 为 2 空格），多出一个 `}`

## 最终方案

修正 `.es-date` 缩进为 2 空格，删除多余的闭合 `}`。

## 验证

- `npx vite build` 通过 ✓

## 预防

- `edit` 工具的 `oldString` 缩进须与文件实际缩进严格一致，否则可能匹配到错误位置导致缩进错乱
- SCSS 大括号不匹配时，用 `npx sass <file> --no-source-map` 单独编译可快速定位行号（比 `vite build` 错误信息更精确）
- 替换含嵌套选择器的样式块时，替换后立即构建验证
